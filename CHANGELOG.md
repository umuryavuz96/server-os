# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com), and the project follows [Semantic Versioning](https://semver.org).

## [Unreleased]

### Added
- House page: a Rooms view with eye-level renders (`bun run house:render --views cams.json` writes `data/house-views`, served at `/house/views`): horizontal gallery, Day/Night, tap to open full screen and swipe.
- House 3D: outer walls stay full height and fold down (about 200 ms, with hysteresis) only on the side the camera is on, so the TV wall and the rest of the interior are always visible from behind. Needs `bun run house:render --glb` once.
- House page: a live 3D dollhouse of the house (three.js) with Home Assistant devices pinned in their rooms. Floors one at a time or all side by side, orbit and zoom (touch too), room names, and rooms that glow warm with their lights (brighter with brightness). Pins show on/off/unavailable and sensor values; tap one for its dashboard card (toggles go through the `/ha/call` allowlist). The house is data, not code: `config/house.json` (`spec/house.schema.json`: storeys of rectangular rooms in metres, doors, windows, fixtures, a `mirror` flag), shipped with a default model. Devices are placed by their HA area (`haArea` per room), the rest wait in a tray; edit mode drags pins and tray devices into rooms (or tap, then tap the room) and saves them. API: `/ha/areas`, `/house`, `/house/layout`, `/house/pins`, `/house/devices` (a Markdown list to confirm). See docs/house-3d.md.
- Dashboards: Home Assistant cards. New types `entity` (any value with its unit), `toggle` (switch, with optimistic update and rollback), `climate` (current temperature, setpoint −/+), `camera` (a still every 5 s, click to enlarge), `media` (now playing, play/pause, volume), `history` (line chart of a numeric entity), `button` (run a scene or script) and `group` (opens a set of cards). The card editor has an entity picker (search by name, id or room, filter by domain), and `docs/examples/house-dashboard.json` is a whole-house example. State is live: the server holds one WebSocket to Home Assistant and pushes only the entities a dashboard shows (polling every 5 s if the socket can't open). The token stays on the server. Service calls are limited to `integrations.homeAssistant.allowDomains` (default: light, switch, fan, climate, media_player, scene, script, input_boolean, cover; never locks or alarms unless you add them) and must name their entities. API: `/ha`, `/ha/entities`, `/ha/call`, `/ha/history/{id}`, `/ha/camera/{id}`. See docs/configuration.md.
- Voice chat: the Voice page opens on a full chat with the voice assistant (its bot session, live over the feed). Typed messages go in as `[Chat] …`, spoken ones as `[Voice] …` / `[Voice tr] …`. Answers render as sanitized Markdown with tables, images, links and code, the pages from the turn's WebSearch / WebFetch steps as source cards (title, domain, favicon, snippet), and component blocks the agent writes as fenced JSON: ```` ```card ````, ```` ```sources ```` and ```` ```chart ```` (docs/voice-chat.md); speech skips them. A thinking row with what it is doing ("Searching the web for …"), Stop, Retry, Copy, Read out, auto-scroll that waits while you read back, "show earlier" and earlier conversations. Voice mode: a big mic (hold to talk, tap for one sentence, or hands-free with silence detection), a level meter, barge-in, and the answer spoken in the browser as it streams. The assistant's name comes from `integrations.houseVoice.name` or its CLAUDE.md heading; the Voice tabs no longer hardcode one.
- Speech to text on the server: `POST /voice/transcribe` decodes a browser clip with ffmpeg and transcribes it with whisper.cpp (`integrations.stt`, defaults to `whisper-cli` and `~/.whisper-models/ggml-small.bin`). Capability `stt`.
- Microphone fallback chain, with a picker: this browser (needs https or localhost; on plain http the page says why and links the https address), your phone (a QR code opens a mic page on the panel's https address that pairs with the normal one-time device code and posts clips to the chat's mic session, `/voice/mic…`), the desk speaker (house voice), and Sonos, listed as not possible: Sonos has no API for its microphones. Answers can be played on a Home Assistant speaker such as a Sonos instead (`integrations.speakers`, `/voice/speakers`, output only).
- Voice chat as a TV screen: `#voice-chat?kiosk=1`, full screen and zoomed for reading at a distance, D-pad focus navigation (arrows, Enter, Back), the WebView's own audio input when it has one, else the phone pairing QR large in the middle.
- The transcript parser keeps the links of WebSearch and the URL of WebFetch steps (`sources`, `summary` on feed items).
- Usage tab: every paid or metered service on the device, found automatically from variable names in the env file (`costs.envFile`), signed-in command line tools, installed apps and profiles, matched against a provider registry (`server/modules/usageProviders.json`, one entry per service). A card per service with the plan, usage bars with reset time, monthly cost, status (OK, near limit, error, no data), last check and a billing link; near-limit first, then by cost. Usage is read from each provider's own API where one exists (Claude Code, ElevenLabs, Cloudflare, GitHub, OpenAI and Anthropic with an admin key), cached 10 minutes with backoff on 429, and secret values never leave the server. Set your own price, plan name, renewal day or hide a service from the card (`config/usage.json`, owner only). API: `GET /usage`, `POST /usage/refresh`, `PUT /usage/overrides/{id}`.
- Costs tab: what it takes to run the server per month, "about X / month", split into counted and estimated, with a 30-day trend. Subscriptions and paid services from Usage, electricity (a Home Assistant power sensor via `costs.power.haEntity`, else an estimate from CPU load and the machine's idle and full-load watts at `costs.kwhPrice`), fixed costs you add (domains, VPS, hardware), and the server's Claude Code use per bot and project from the session transcripts, priced at API list prices (`modelPrices.json`) as "what it would cost", never added to the total. API: `GET /costs`, `PUT/DELETE /costs/fixed/{id}`. See docs/configuration.md.
- Jobs: the ID card is visual. A hero with a colour-coded risk badge (shield read-only, pencil writes, triangle destructive), then tiles for Apps, Disk, Data, Tools, APIs, Secrets, Model and Reports, each with its own icon. Apps show their real icon from the Apps tab, other tools and APIs show brand logos (selfh.st via jsDelivr) or a Lucide icon, disk paths show a folder, log, cache or database icon with a deleted, truncated or written badge, and secrets are key chips. Each job in the list shows up to three of its icons. An optional `icons` map in the card pins an icon for an entry that is not matched by name.
- Jobs: every job has a full ID card, and the Jobs tab shows it. A card says what the job does and why, which apps and disk paths it touches, what it uses (tools, APIs, secret variable names, model) and its risk (read-only, writes, destructive). Crontab jobs are keyed by name and launchd agents by label in the cards file (`integrations.cron.cards`); built-in jobs carry the fields in `job.yaml`. The list shows a risk pill, jobs without a complete card get a "No description" pill, and the header counts them (tap to filter). `bun run server/cli.ts jobs:check` lists incomplete cards and exits 1. Creating a built-in job without `about`, `touches`, `uses` and `risk` is rejected with a message naming what is missing (API, MCP `create_job` and the editor); existing jobs keep working. See docs/configuration.md.
- Bots: answer Claude Code permission asks from the panel. A "Needs your OK" card (tool, readable summary, full details) with Allow, Always allow and Deny sits at the top of the bot's Info panel, above the chat on phones, and the bot shows an "OK?" badge in the list. It works through a `PermissionRequest` hook, `agent/hooks/permission-relay.sh`, that you add to the bot's Claude Code settings; if nobody answers within the wait (`SD_APPROVAL_WAIT`, default 10 min) or the server is unreachable, the hook prints nothing and Claude Code asks in the terminal as usual. `bots.approvalPing` can run a command (for example a Telegram sender) when an ask arrives. API: `POST /approvals/hook` (this machine only), `GET /bots/:ch/approvals`, `POST /bots/:ch/approvals/:id/decide`.

## [0.1.2] - 2026-10-28

### Added
- Voice page: one page for voice mode and the desk speaker, with a voice picker grouped by language. Every voice has a play button; its sample is made once and cached under `data/voice-samples/`, and only one sample is made at a time. The page also has a catalog of open-source voices to try (Turkish support, cloning, licence and size taken from each model card, with links to the repo and demo). The separate Voices page is gone, and `#voices` links open `#voice`.
- Cloud voices (ElevenLabs) for voice mode: a "Cloud voices" switch and live usage (credits used / limit, reset date, plan, about how many minutes of speech are left). The key comes from the `integrations.elevenLabs.keyEnv` variable (default `ELEVENLABS_API_KEY`) and needs the "User: read" permission for the usage numbers. With the switch off, cloud voices are spoken by a local voice.
- Desk speaker language setting.
- Bots: the inspector lists only running jobs and agents. Tap one for a drawer with its details and the sub-agent's conversation (`GET /bots/:ch/jobs/:id/log`, secrets redacted).
- Jobs: launchd agents with a configured label prefix (`integrations.cron.launchd`) appear on the Jobs tab with their schedule, state, log and a Run now button.
- Git checkouts (developer mode) get a working Update button: it fetches, fast-forwards to origin, installs dependencies if the manifests changed, rebuilds the panel, restarts through the service manager and rolls the checkout back if the new commit doesn't come up. It refuses, with the reason shown on the card, when the branch doesn't track origin, tracked files have local changes, or local commits aren't on GitHub. Nothing is stashed, discarded or forced.

### Changed
- Panel icons are now Lucide icons, and language sections show SVG flags.
- GitHub release notes are now the matching CHANGELOG section plus the compare link, so the update card shows what changed.

### Fixed
- Overview: the Claude usage refresh button now says when Anthropic is rate-limiting usage reads, instead of doing nothing.
- Tests run against a throwaway `SERVER_OS_HOME` and no longer write into the real data folder.

## [0.1.0] - 2026-10-28

First public preview.

### Added
- Self-updater: signed releases (Ed25519 over SHA256SUMS), one-tap or nightly updates from the panel, health-checked switch with automatic rollback, last two versions kept. Homebrew installs defer to `brew upgrade`; git checkouts never self-apply. See `RELEASING.md`.
- Mac screen as a modal over the page with floating controls and a picture-in-picture that grows and shrinks in place.
- Permissions how-to: step-by-step mini visuals per permission, popups triggered directly where macOS has one, live status that closes the screen once a permission is on.
- Discover: rotating editor's picks (hero and side cards), adaptive layouts for every tab from phone to ultrawide.
- Mac screen: with `integrations.screen.enabled`, the panel shows this Mac's screen in the browser (noVNC 1.7.0 over `GET /api/v1/screen/ws`, piped to Screen Sharing on 127.0.0.1:5900). Permissions → "Fix on the Mac screen" opens the right System Settings pane, shows the screen, and re-checks when you close it. Owner only (admin key or a paired device, never the agent), same-origin, one session at a time, idle timeout and hard cap, audited. Apple's login (RFB type 30) works on plain http too, through a small AES fallback for browsers without WebCrypto. The setup wizard reports whether Screen Sharing is on. See `docs/permissions.md`.
- macOS permissions: the server lists the privacy permissions it needs (Full Disk Access, Local Network, volumes, folders, microphone) with why, which program holds the grant, status and a System Settings link. Shown in System → Permissions, as an Overview banner when a required one is missing, in the setup wizard (new step 8) and at `/api/v1/permissions`. See `docs/permissions.md`.
- `integrations.houseVoice` and `integrations.channelsDir` replace the hardcoded desk-speaker paths and tmux session names; the feature stays off unless configured.
- Live web panel: vitals with range charts, apps with on/off switches, jobs, alerts, ports, storage, logs and traces over one SSE stream.
- Discover: search self-hostable apps from several catalogs and install with Docker Compose or Homebrew.
- Built-in scheduler with shell, Claude prompt and HTTP jobs, run history and webhooks.
- JSON dashboards, structured logs with OpenTelemetry field names, trace ids, audit log, optional OTLP export.
- Versioned API under `/api/v1` described by `spec/openapi.yaml`, with device-token pairing.
- Root agent kit (`agent/`): instructions, skills, an MCP server and an audit hook.
- Setup wizard (`server-os-setup`) for macOS and Linux, launchd and systemd units, Homebrew formula.
- Demo mode: `SERVER_OS_DEMO=1` serves made-up data for screenshots and trying the UI.
- Native bot manager: without Claude OS, Server OS runs Claude Code bots itself in tmux sessions (`sos-<bot>`, prefix configurable under `bots.prefix`): create (model, effort, permission mode, optional Telegram token variable), start fresh or resume, stop, restart, delete, live terminal, send prompt, history and CLAUDE.md editing. New bot folders are pre-trusted so they don't stall on the trust prompt.
- Bot workspaces for native bots: per-bot scope (folders, network, Claude Code sandbox), tool presets (safe, dev, full) with custom allow/deny rules, skill/plugin/MCP picker, ticked `~/.env` secrets only (`env -i` launch), optional isolated `CLAUDE_CONFIG_DIR`, Telegram owner pre-approval in `access.json`, and an identity block in `CLAUDE.md`. All written as Claude Code config in the bot's folder; edited in the new Workspace tab.
- `bots.provider: both`: Claude OS bots and native bots side by side in one Bots list. Native bots can adopt an existing folder in place (`dir`), keep their agmsg team (`team`) and Telegram state folder (`telegramStateDir`), and keep their own `.mcp.json` servers on. New workspace switch *Read anywhere*. Native bots get `~/.bun/bin` on their PATH (the Telegram plugin runs on bun).
- Native bots no longer inherit the owner's global `~/.claude/CLAUDE.md` and rules by default: a per-bot "Use my global instructions" switch controls `claudeMdExcludes` in the bot's settings.
- Native bots keep their agmsg inbox stream alive: Claude Code ends a Monitor after 30 minutes and agmsg doesn't re-arm it, so Server OS reads the expiry from the bot's transcript and, once the bot is idle, sends one short re-arm turn (no model polling).
- Bots talk to each other: every native bot joins the agmsg team `bots.team` (default `server-os`) with monitor delivery; the Bots tab shows each bot's team and last messages, and how to install agmsg when it's missing.

### Notes
- New native bots default to the `dontAsk` permission mode with the `safe` preset and only their own folder in scope.
- The Bots tab uses Claude OS when `integrations.claudeOS` is set (as before) and the native manager otherwise; `bots.provider` picks one explicitly. Without tmux or the `claude` CLI and without Claude OS, the tab is hidden.
- Machine-specific integrations (`integrations.cron`, `integrations.catalog`, `stateDir`) are off unless set in `config/server-os.yaml`.
- The pre-rename names `SERVER_DASH_HOME`, `config/server-dash.yaml` and the `X-Server-Dash-Secret` webhook header are still accepted.
